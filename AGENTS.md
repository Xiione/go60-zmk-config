# Go60 development

- Use `xiione/` branch names and concise area-prefixed commits. Keep the config checkout as the build entry point. Initialize submodules with `git submodule update --init --recursive`. The sibling firmware checkout is optional.
- The shared source pin is in `firmware.env`. The [firmware fork](https://github.com/Xiione/go60-zmk-firmware) carries the descriptor backport once. Compare dependency updates to the pinned MoErgo PR36 base.
- Daily combined firmware: `./build.sh` (Windows: `build.bat`). Historical tuning LH: `tools/scroll-tuning/build-left.sh`. Raw pad probes LH and RH: `tools/pad-probe/build.sh`. The daily and tuning profiles have separate listener chains. Each build emits a UF2 and a sibling manifest. The recorder instructions cover parameter overrides and USB/Bluetooth routing.
- Run `python3 -m unittest discover -s tools/scroll-tuning` and `python3 -m unittest discover -s tools/pad-probe`. Compile the macOS recorder with `swiftc tools/scroll-tuning/Capture.swift -o /tmp/go60-scroll-capture`.
- For hardware recovery, connect USB and power on holding T3 + C3R3 on the affected half (Enthium left Esc + A, right Enter + T). Restore the operator-confirmed image to the matching GO60LHBOOT or GO60RHBOOT volume. The existing flash script targets every mounted Go60 bootloader. Mount only the intended half for a side-specific image. Keep vendor flash partitions and board power limits in view when reviewing hardware changes.
- See the [experiment log](docs/cirque-experiments.md) for the archive, evidence quality and roadmap, the [tuning guide](tools/scroll-tuning/README.md) for recording, and the [pad guide](tools/pad-probe/README.md) for packet interpretation. Keep device measurements, host observations and hardware confirmation distinct.
